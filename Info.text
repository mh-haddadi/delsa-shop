===== تنظیم اولیه (فقط یک بار) =====

# معرفی خودت به Git
git config --global user.name "اسم تو"
git config --global user.email "ایمیل تو"


===== شروع پروژه =====

# ساختن مخزن Git در پوشه‌ی فعلی
git init

# دانلود یک پروژه از GitHub روی سیستم
git clone <آدرس-پروژه>

# وصل کردن پروژه به مخزن GitHub
git remote add origin <آدرس-مخزن>


===== کار روزمره =====

# دیدن وضعیت: کدوم فایل‌ها عوض شدن یا اضافه شدن
git status

# اضافه کردن همه‌ی فایل‌ها به جعبه‌ی کامیت
git add .

# اضافه کردن فقط یک فایل
git add نام-فایل

# بستن جعبه و ذخیره‌ی یک نسخه با توضیح
git commit -m "توضیح کار"

# فرستادن کامیت‌ها به GitHub
git push

# گرفتن آخرین تغییرات از GitHub
git pull


===== دیدن تاریخچه و تغییرات =====

# لیست کامیت‌های قبلی
git log --oneline

# دیدن اینکه دقیقا چه خط‌هایی عوض شده (قبل از add)
git diff


===== اصلاح اشتباه‌ها =====

# تغییر پیام آخرین کامیت (فقط اگر هنوز push نکردی)
git commit --amend -m "پیام جدید"

# برگرداندن یک فایل به آخرین نسخه‌ی کامیت‌شده (تغییرات ذخیره‌نشده از بین می‌رود!)
git restore نام-فایل

# درآوردن فایل از زیر نظر Git ولی نگه داشتنش روی سیستم
git rm --cached نام-فایل


===== شاخه‌ها (برای وقتی که یک قابلیت جدید می‌سازی) =====

# دیدن لیست شاخه‌ها
git branch

# ساختن شاخه‌ی جدید و رفتن به آن
git switch -c نام-شاخه

# رفتن به یک شاخه‌ی موجود
git switch نام-شاخه

# ترکیب یک شاخه با شاخه‌ی فعلی
git merge نام-شاخه


===== فایل .gitignore =====

# هر خط یک فایل یا پوشه که Git باید نادیده بگیرد
node_modules
.env

ترتیب همیشگی که ۹۰٪ وقت‌ها استفاده می‌کنی:

git status
git add .
git commit -m "توضیح"
git push

اگر می‌خواهی ببینی کل پروژه چه فایل‌هایی دارد، بعد از q این را بزن:
git ls-files




این دو دستور برای ذخیره کردن یک نسخه از پروژه در Git هستند. مثل سیو کردن بازی در Minecraft: اگر بعداً چیزی خراب شد، می‌توانی به همین نقطه برگردی. بعداً هم همین‌ها را روی GitHub آپلود می‌کنی.

git add .
یعنی «همه‌ی فایل‌های پروژه را برای ذخیره آماده کن». نقطه یعنی همه‌ی فایل‌ها. این مرحله مثل گذاشتن وسایل توی جعبه قبل از بستن درش است.
فایل‌هایی که در .gitignore نوشتی (node_modules و .env) در جعبه نمی‌روند، و این همان چیزی است که می‌خواهیم.

git commit -m "init project"
یعنی «جعبه را ببند و رویش یک برچسب بزن». متن داخل گیومه فقط توضیح توست که این نسخه چه بود. init یعنی شروع، پس «شروع پروژه». بعداً مثلاً می‌نویسی "add products API" تا بدانی هر نسخه چه کاری بود.

نکته: اگر اولین بار است که Git را روی این سیستم استفاده می‌کنی و کامیت خطای Please tell me who you are داد، این دو خط را بزن و دوباره کامیت کن:

bash
git config --global user.name "اسم تو"
git config --global user.email "ایمیل تو"




۴. کپی آدرس ریپازیتوری از صفحه‌ای که باز می‌شود:

https://github.com/اسم-کاربری-تو/delsa-shop.git

۵. وصل کردن و فرستادن (در ترمینال):
---
bash
git branch -M main
git remote add origin https://github.com/اسم-کاربری-تو/delsa-shop.git
git push -u origin main

معنی هر دستور

git branch -M main
اسم شاخه‌ی فعلی را می‌کند main. Gitهای قدیمی‌تر اسم پیش‌فرض را master می‌گذارند ولی GitHub از main استفاده می‌کند، پس این خط جلوی ناهماهنگی را می‌گیرد. حرف M یعنی «اگر لازم بود اسم را عوض کن».

git remote add origin <آدرس>
به Git می‌گوید «آدرس ریپازیتوری من در GitHub این است». origin فقط یک اسم برای آن آدرس است (مثل ذخیره کردن یک شماره در مخاطبین).

git push -u origin main
یعنی «کامیت‌های شاخه‌ی main را بفرست به origin». حرف u فقط بار اول لازم است و به Git یاد می‌دهد این شاخه به کجا وصل است. از دفعه‌ی بعد فقط git push کافی است.

نکته

تو ریپازیتوری را با GitHub Desktop ساختی، پس این سه دستور را لازم نداری. دکمه‌ی Publish repository همین کارها را برایت انجام می‌دهد. این دستورها فقط برای کسی است که از ترمینال کار می‌کند. اگر Publish را زدی و پروژه در سایت دیده شد، همین کافی است.
----


آدرس را با آدرس خودت عوض کن.
